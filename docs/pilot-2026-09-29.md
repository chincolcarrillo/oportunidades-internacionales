## Fallos encontrados y correcciones

1. La integración robots.txt usaba el argumento inexistente `bots`; se corrigió a `bot`. El fallo anterior no demostraba un bloqueo del sitio. Se mantuvo verificación TLS y se añadió test con la firma real.
2. La primera extracción confundía elegibilidad incierta con fuera de alcance, producía citas con comillas añadidas y vocabularios inválidos. Se precisó el prompt y se incorporó validación de valores antes de reconciliar.
3. Se evita llamar a IA cuando el texto descargado tiene menos de 200 caracteres; un main vacío o muy corto permite buscar texto en el cuerpo HTML ya descargado.
4. El modelo confundió gastos indirectos no financiables con ausencia de cofinanciamiento incluso después de precisar el prompt. Ese dato ahora requiere evidencia explícita sobre cofinanciamiento; la exclusión de overhead no basta.
5. Los JSON futuros del piloto conservan null como null. Los archivos de la primera ejecución serializaron null como objeto vacío; conservarlos como evidencia de esa ejecución, no reimportarlos como canónicos.

## Corrección posterior: la fuente Leakey es válida

Tras la observación del usuario se diagnosticó el HTML recibido directamente por R: HTTP 200, 241.094 caracteres de HTML y 10.949 caracteres de texto dentro de main. El parser sitúa main/article bajo `/html/body/div/header`. La limpieza eliminaba todos los header, destruyendo ese contenido y dejando únicamente 15 caracteres (“Skip to content”). No era falta de información de la fuente ni se demostró dependencia de JavaScript.

Se eliminó la regla destructiva para header y se seleccionan main/article sin duplicar nodos anidados. Se añadió una prueba offline que reproduce esa estructura. Se conserva la URL oficial original; no hace falta buscar una fuente alternativa por este fallo. Esta comprobación no consume API ni cambia datos canónicos.
